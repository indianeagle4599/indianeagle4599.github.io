AudioBench

I built AudioBench for Amplify Dental to choose the right speech-to-text model. It tests models on noisy, accented, and distant-microphone audio and keeps the hand-checked transcripts and test setups, so the team never redoes that work.

Amplify Dental

Built for Amplify Dental

AudioBench is the evaluation and annotation workbench I built for Amplify Dental's transcription work. On a small team, every hour spent repeating transcription, labelling, or benchmark setup is an hour not spent on the product. I built each part to be reused.

Distant speech, room noise, accents, and microphones can change which model performs best. AudioBench keeps hand-checked reference audio, named preprocessing pipelines, and local or cloud speech-to-text systems in one results view so the team can compare them without repeating setup.

Models are sorted so the strongest overall result appears first. Heatmaps and a complete results table show interactions between models, datasets, and audio treatments that one average score would hide.

Solve it once, then reuse it

I built the annotation interface around the audio instead of keeping transcripts in a separate spreadsheet. It shows the waveform, compares original and cleaned audio, changes playback speed, and saves the hand-written reference transcript. The sample library keeps the same reference audio and transcripts with condition tags and completion status. The live test runs one ready speech-to-text system on a hand-checked sample before the team starts a full benchmark.

Each audio-preprocessing workflow is saved by name instead of applied as a one-off file edit. Experiments start from a reusable preset and a preview of the planned model, dataset, and preprocessing combinations. A local Whisper Small server catches setup mistakes before cloud resources are used; cloud GPUs run the same work when an experiment contains many combinations.

How it is built

I built AudioBench so new datasets, speech-to-text models, preprocessing steps, and computing machines can be added through configuration. Python and FastAPI run locally first, and one shared config file lists every local and cloud speech-to-text model, so swapping one is a config change.

Public data and models

The suite contains 6 public speech datasets: AMI headset (IHM), AMI distant mic (SDM), VoxPopuli, Common Voice, VCTK, and LibriSpeech. Together they cover distant microphones, accented English, varied speakers, and clean read speech.

The recorded interface includes Whisper Large v3 through Hugging Face and Faster-Whisper, Whisper Small, Kyutai STT, Google MedASR, Moonshine Base, and Qwen3-ASR. Its audio options include unchanged audio, audio adjusted for speech recognition, audio adjusted for human review, cleaned audio, and longer sequences of clean-up steps assembled in the lab.

Word error rate is the share of words the model got wrong. Character error rate is the same at the letter level. Real-time factor is processing time divided by audio length.
