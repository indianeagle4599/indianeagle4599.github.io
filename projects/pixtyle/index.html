Pixtyle

I built Pixtyle to turn photos and videos into wallpaper-like or cartoon-like images using colour clustering, Fourier filtering, and edge detection.

GitHub

What it is

My pollution-monitoring work showed me how strongly image filters change what a vision system sees. I built Pixtyle to make those signal-processing effects visual, controllable, and easier to reason about. It supports single images, folders, and video through colour clustering, frequency filtering, edge stylisation, and combined pipelines.

Many image filters create recognisable visual styles, which makes exploring signal processing more intuitive. Because convolutional neural networks also respond to image structure and edges, seeing what a filter changes helps me reason about what a model receives.

How the styles work

Each run selects one transform. The names below are the project’s own style names; the paragraphs explain what they do.

K-means

kmeans_cluster reduces the image to a compact colour palette. Pixels are clustered on colour, optionally weighted with spatial position, then replaced with their centroids and optionally blended back toward the original with edge enhancement. The visual aim is posterised, region-like colour rather than line-first stylisation.

Enhanced

enhanced_cluster blends Euclidean and angular distance at reduced resolution, then overlays a Sobel edge tint and colour-pop finishing. It is the stronger segmented-and-outlined alternative when K-means looks too soft on a busy scene.

Edge Pop

edge_pop is a standalone edge styliser. Sobel and Canny can run on GPU through the Torch backend; Scharr, Prewitt, and Laplacian are OpenCV-only. Thresholds and blend modes (ink, glow) push outline or glow over the pixels you already have.

Fourier

fourier_animate stylises in the frequency domain: FFT band-stop and radial masks with presets (anime_soft, anime_bold, cartoon, watercolor, graphic_novel), then colour finishing. The look comes from which frequency bands survive, not from palette size.

Combo

cartoon_combo composes optional Fourier-derived detail maps as an auxiliary extractor (not a destructive first pass), K-means colour flattening, Edge Pop lines, then colour-pop or contrast finishing. On video, the edge mask can be EMA-smoothed across frames.

One transform is selected per run. Defaults live in pixtyle_config.py; CLI flags override them.

Video stability

Clustering each video frame independently can make palettes flicker from frame to frame. Pixtyle carries cluster centroids across neighbouring frames (temporal centroid smoothing) so colours stay more stable on a continuous shot. Scene changes are detected by comparing per-channel histograms with an L1 distance and hysteresis (SceneChangeDetector, method hist). A detected cut calls reset_state, so the previous shot’s palette is not blended into the next.

Technical implementation

Transform architecture

Showcase stylisers subclass TransformBase and implement the same interface: process_numpy, process_torch, reset_state, and describe. They register in processors/registry.py. A run selects one transform; pixtyle_config.py holds defaults and CLI flags override them.

That isolation is the point: decode, batch, write, and (for video) temporal hooks stay the same while the styliser is swapped.

Processing pipeline

Input is a single image, a folder, or a video.

OpenCV decodes frames. Image folders are grouped into uniform-shape batches so tensors stay consistent. The selected transform runs on each batch. Video then encodes the stylised clip; when audio_merge is enabled, ffmpeg remuxes the original audio onto the processed picture.

Route: input → decode / batch → selected transform → temporal handling where the styliser keeps state → encode → optional audio remux.

Acceleration and backends

Torch is a hard dependency. Every showcase transform has both NumPy and Torch implementations; the CLI auto-selects a GPU when detect_torch_device finds one.

GPU execution applies to the Torch paths for clustering, Fourier processing, and Sobel/Canny edges. Scharr, Prewitt, and Laplacian remain OpenCV-only. GPU is not claimed for the whole toolkit.

Image-processing primitives

Colour / clustering. K-means groups pixels by colour (optionally with spatial weighting) and replaces them with centroids — palette reduction / posterisation. Enhanced clustering uses blended Euclidean and angular distance at reduced resolution, then colour-pop finishing.

Frequency. Fourier helpers build a radius grid and apply band-stop / radial masks in FFT space, then colour finishing. Presets (anime_soft, anime_bold, cartoon, watercolor, graphic_novel) choose which bands survive.

Edges. Shared extractors cover Sobel, Canny, and FFT edges (NumPy and Torch). Edge Pop also exposes Scharr, Prewitt, and Laplacian through OpenCV, with ink and glow blend modes.

Combined pipeline. Combo uses optional Fourier-derived detail as a cue, K-means for colour regions, Edge Pop for lines, then colour-pop or contrast finishing (including YUV luminance restore). It does not treat Fourier as a destructive first pass.

Video-specific state

Temporal centroid smoothing carries cluster centres across neighbouring frames so a continuous shot does not re-seed a new palette every frame.

Combo can EMA-smooth the edge mask across frames (edge_mask_ema).

SceneChangeDetector compares concatenated per-channel histograms with L1 distance and hysteresis. On a cut, reset_state clears centroid history (and Combo’s edge-mask cache) so the next shot starts clean.

Optional super-resolution

An image-only TensorFlow SavedModel step (--sr) can upscale after stylisation. TensorFlow is not required for the main pipeline. The vendored sr/ training project is a separate environment, not Pixtyle’s core architecture.
