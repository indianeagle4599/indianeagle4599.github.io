Aftersight

I built Aftersight because my own photo library was disorganised and hard to search. It uses language models to organise images and find them by meaning, visible text, or metadata—not just filenames.

GitHubBlog

What it is

I was fed up with how disorganised my own photo library was, so I built Aftersight to explore how language models could organise memories and make them easier to search. A vision-language model—an AI model that connects images and text—describes each image once, and later searches reuse that record.

Approach

  • I fingerprint each file and reconcile the available timestamps before indexing, giving date-based search one chosen date instead of relying on a single filesystem timestamp.
  • MongoDB stores the main image record. ChromaDB searches scenes, keywords, visible text, and metadata separately, then weighted reciprocal rank fusion combines those ranked lists.
  • Search runs locally after the description step. Each result shows why it was returned through its source image, generated description, metadata, component ranks, combined score, and contributing search method.
