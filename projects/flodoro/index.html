Flodoro

I built Flodoro for people who want a Pomodoro timer, tasks, session history, and local music on one page without an account or application server.

GitHubLive Demo

What it is

Flodoro is a Pomodoro timer and lightweight task manager that runs as a single static webpage. Work and break settings, tasks, history, themes, and notification preferences stay in the browser, while music is optional and comes from folders the user selects on their own machine.

The goal is a focused workspace without accounts, sync, or a backend.

Why music belongs here

Timer, current task, and local playback live on the same surface so a focus session does not require switching to a separate music player. Playback remains user-controlled — starting the timer does not start a track — while notification chimes briefly lower the music volume so session alerts are still audible.

How a session works

Flodoro supports work, short-break, and long-break sessions with configurable durations. A completed work session moves into the next break automatically; after the break, the next work session is started manually. A break can be postponed once, returning to work with five extra minutes.

Tasks can be kept alongside the timer, with completed sessions contributing to the local history and statistics views. Preferences, tasks, and history survive reloads; the live countdown itself does not.

Local music

Flodoro does not ship a music catalogue or require a streaming login. The user selects a local music folder, and the app builds playlists from that folder and its first-level subfolders.

Playback stays inside the page through the browser audio element, with play/pause, previous/next, mute, volume, and scrubbing controls.

On Chromium browsers, Flodoro can remember the selected folder handle in IndexedDB so it can be reconnected later. The audio files themselves are never copied into browser storage. Other browsers can use the directory file-input fallback for the current session.

Local-first implementation

Static architecture

Flodoro is built with vanilla HTML, CSS, and JavaScript and runs without an application backend. The hosted page is the same static app.

Browser storage

Tasks, history, preferences, notification settings, themes, and selected music/track identifiers are stored locally in the browser. Chromium folder handles use IndexedDB so access can be remembered without storing the underlying audio files.

Music playback

Selected files are played through the browser's <audio> element. Folder selection uses the File System Access API where available, with the existing directory-input fallback elsewhere. Music playback remains independent from the Pomodoro timer except for volume ducking during notification chimes.

Timer behavior

The timer manages work, short-break, and long-break state in the page, with pause, reset, duration adjustments, session transitions, and notifications.

Preferences, tasks, and history persist across reloads; the active countdown does not.

Design constraint

Flodoro is intentionally serverless. Accounts, cloud sync, and a shipped music catalogue stay out of scope; features are designed to work from the static page and the user's own browser/device.
